## 1. 目的

TOKIUM「【直アポプラン】役職なし・年商300億以上」（通称**直アポ大**、単価87,500円）のリストに、
**実際は年商300億円未満、または条件を満たさない企業が混入している**。

これによって起きている事故:

> アポインターが「300億以上のリスト」だと信じて架電しアポを獲得 → 後から条件外と判明 → **計上できない**

**アポインターはアポ獲得の成果報酬で稼働している。計上されなければ無報酬になる。**
原因が本人の落ち度ではなくリスト側の誤りであるため、最優先で潰す必要がある。

したがって本作業のゴールは「売上高を調べること」ではなく、
**架電前にリストから除外すべき企業を確定させること**である。

### 誤りの方向と重み

| 誤り | 結果 |
|---|---|
| 実際はNGなのに「300億以上」と判定 | アポインターが無報酬になる。**最も避けるべき** |
| 実際はOKなのに「確認不可」と判定 | 架電できたはずの企業を失う。これも実害 |

数字をひねり出すことは絶対にしない。**確信が持てない場合は「確認不可」が正しい結論。**

### 3-7. 指標は「売上高」

- **「収益」「利益」ではない**
- IFRS等で「売上収益」表記なら売上高と同義として採用。H列に原文表記を注記
- **銀行・保険は「売上高」という科目が存在しない** → 「経常収益」を採用し、H列に明記
- 会計基準変更（総額表示→純額表示）で新旧が乖離する場合は、
  **最新基準の売上高をG列に採用し、H列に「旧基準では○○億円」を必ず併記**

### 3-8. 決算期の鮮度

- 直近3期以内を採用
- それより古いものしか無い場合はG列「確認不可」、H列に「最新の売上高が非公表。○年○月期時点では○○億円」

## 5. 実行方法

### 5-1. 全体構成（二段パス）

1社1エージェントは高コスト（実測88k tokens/社）なので、**15行ずつのブロック**に分割する。

```
1次調査（Sonnet）: 295ブロック × 15行 = 全4,422行
   ↓ ×/△ を付けた行だけ
再検証（Opus）  : 1次が浅く諦めた可能性を疑って掘り直し、覆れば上書き
```

`pipeline()` で組むこと。ブロックごとに1次完了 → 即再検証に流れるので待ちが出ない。

**リクエスト数の上限は設けないこと。** 「最大6リクエスト」のような制限を入れると
確認不可が量産され、架電できたはずの企業を失う。

### 5-2. エージェントの手順

1. `ToolSearch` で `GOOGLESHEETS_VALUES_GET` と `GOOGLESHEETS_VALUES_UPDATE` を読み込む
   （`COMPOSIO_MULTI_EXECUTE_TOOL` 経由でも可）
2. `'report1788067240190'!B{s}:F{e}` を読む
3. 各社を調査
4. `'report1788067240190'!G{s}:H{e}` に **必ず担当行数ぴったり** 書き戻す
   - **G列とH列の2列のみ。他の列は絶対に触らない**
   - 行数が合わないと全行ずれるので厳守

**エージェント自身にシートを読み書きさせること。** メインの会話にデータを通すと
コンテキストウィンドウを食い潰す（4,422行で30万トークン超）。

### 5-3. 承認ソース9系統（★これを全部当たってから「確認不可」にする★）

1. 自社HPの 会社概要 / 企業情報 / 会社案内 / 数字で見る○○
2. 自社HPの IR（決算短信・有価証券報告書・決算説明資料・統合報告書・業績ハイライト）
3. EDINET（有価証券報告書・四半期報告書）※法人番号または正式社名で検索
4. TDnet / 適時開示（決算短信）
5. **決算公告**（自社HPの電子公告ページ、または官報）※非上場の株式会社はここに載ることが多い
6. **親会社・ホールディングスのIR資料** ※子会社の場合、親の決算短信や有報の巻末・
   「関係会社の状況」に子会社単体の財務諸表が載っている
7. 公的機関（金融庁、経済産業省、gBizINFO、各省庁の統計・許認可資料）
8. 新聞社の記事（決算期と売上高が明記されているもの）
9. 自社ドメイン内の採用ページ（「数字で見る」「会社データ」等）

**5と6が最も効く。** 実績:
- 伊予銀行・京都銀行 → 持株会社の決算短信巻末の子会社単体財務諸表から経常収益を取得
- 綿半ソリューションズ → 綿半HD有報「関係会社の状況」から単体376.34億円
- フォンテラジャパン・豊田スチールセンター → 官報決算公告から取得
- ユニ・チャームプロダクツ → 自社サイトの決算公告PDFから2,568.87億円

## 6. 既知の落とし穴

### 6-1. 桁の誤読（最重要）

- `1,127億9千万円` = 1127.9億円（複合単位）
- `41,266百万円` = 412.66億円
- ゼロ幅スペースや空白で小数点が分断されることがある。
  実例: `398. 64億円` を `64億円` と誤読した（正しくは398.64億円）
- **必ず検算すること。桁の誤りは致命的。**

### 6-2. 同名企業の取り違え

全国に同名法人が複数ある社名が多数含まれる（株式会社オータニ、株式会社モリタ、株式会社アルシエ等）。
**B列の法人番号で必ず照合すること。** 所在地・設立年・事業内容が合わなければ別法人。
**別会社の数字を書く方が、空欄より危険。**

### 6-3. 会計基準変更による数字の激変

実例:
- **株式会社デジタルホールディングス** — 2025年12月期の売上高131.02億円。
  だがネットに出回るのは616億円（収益認識基準適用前の総額表示）。
  さらに博報堂DYHDのTOBで子会社化・2026年3月19日上場廃止。
- **豊田スチールセンター（現・豊通メタルソリューションズ）** — 189.65億円（第66期）。
  旧基準では686.64億円（2021年3月期）。

**アポインターが古い数字を見て誤判断する導線になる。必ずH列に旧基準値を併記すること。**

### 6-4. 連結と単体の取り違え

グループ連結値を子会社単体の売上として書くのは絶対NG。
実例: JALUX 単体426.92億円 / 連結892.26億円 → **単体を採用**

### 6-5. 一時要因による膨張

実例: **京都銀行** 2026年3月期の単体経常収益3,546.84億円には、
任天堂株等の政策保有株式売却益1,771.94億円が含まれる。平常時は1,500〜2,300億円規模。
H列に注記すること。

### 6-6. 禁止ソースの数字が広く流通している

実例:
- **加藤化学** — 「2024年3月期 761億8,200万円」が就活会議・Baseconnect・doda・
  マイナビ転職・OpenWork に掲載。承認ソースには一切記載なし。→ **確認不可が正解**
- **フォンテラジャパン** — 「800億2500万円」がYahoo!しごとカタログ・SalesNow・Baseconnectに掲載
- **カーギルジャパン** — 「195,241百万円」がNIKKEI COMPASS・SalesNow・NewsPicks等に掲載。
  旧本社住所と紐づいており株式会社時代の古いデータの可能性

### 6-7. 社名変更・合併済み

実例:
- 豊田スチールセンター → 2026/4/1 豊通メタルソリューションズ株式会社
- 399行目までで1件、2026/4/1にソフトバンク(株)へ吸収合併され法人格消滅した企業を検出

## 7. 未解決の確認事項（先方確認が必要）

### 7-1. 官報決算公告のまとめサイト（catr.jp）は承認ソースか ★要確認

決算公告ルートで取得した行の出典URLが `catr.jp`（官報決算公告を収録した民間サイト）に
なっているものがある。**官報そのものは公的情報だが、catr.jp は官報ではない。**

- 官報のオンライン無料公開は直近90日分のみで、過去の決算公告は遡及できない
- そのため catr.jp のような二次サイトを使わざるを得ないケースが出る
- **先方がこれを承認ソースとして認めるか未確認**

→ 濱本さんに確認すること。認められない場合、該当行は `△ 確認不可` に倒す必要がある。
