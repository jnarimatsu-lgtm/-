# TOKIUM 直アポ大 — G列・H列の検証

4,422行の企業リストについて、G列（売上高）とH列（判定・出典）が本当に正しいかを
検証し、結果をI列に、出典をJ列に書き出したものです。

判断基準は `RULES.md`（ご提供いただいた仕様）が唯一の根拠です。

## 納品ファイル（`results/`）

| ファイル | 用途 |
|---|---|
| **`IJ_columns_only.csv`** | **これをシートのI2セルに貼ってください。** I列・J列の2列だけ、全4,422行・欠番なし |
| `IJ_columns_short.csv` | 同じ内容で、I列を §4 の1セル300字以内に収めた版 |
| `IJ_paste_FULL.csv` | 取引先ID・法人番号・元H判定・最終判定つきの照合用 |
| **`G_column_corrections.csv`** | **G列の訂正一覧。** どの値が誤りで正しくは何か |
| **`OPEN_QUESTIONS.md`** | **先方にご確認いただきたい事項。** §7-1 が最優先 |

貼り付け用ファイルは**必ず全4,422行**で出力しています。検証済み行だけを詰めた表を
貼ると最初の欠番以降が1行ずつずれ、元データの2707〜2719行で実際に起きた事故
（他社の売上高が別の会社の行に入る）を再発させるためです。

## 要確認リスト（`results/`）

| ファイル | 内容 |
|---|---|
| `thin_margin_watchlist.csv` | 架電可のうち400億未満。基準300億に近く、少しの誤差で反転する |
| `inferred_number_risk.json` | 出典の数値ではなく推定で架電可になっている行 |
| `reorganization_rows.json` | 会社分割・事業承継があり、売上が移管先に付いている可能性 |
| `exclude_regardless_of_catr.json` | §7-1 の回答を待たずに今すぐ除外できる行 |
| `koukoku_bs_only.json` | 決算公告が貸借対照表のみで、売上高が構造的に存在しない行 |
| `same_name_pairs.json` | 同名別法人のペア（§6-2） |
| `gbiz_hojinbango_mismatch.json` | 出典の法人番号がB列と異なる行（大半は §3-3 の親子確定で正常） |

## 検査

```sh
sh tokium/final_check.sh
```

進捗・§3-6ガード・貼り付け整合（行数/連番/取引先ID）・検索枠切れ・各リストの件数を
まとめて確認します。

## この環境の制約（結論の読み方に影響します）

- **WebFetch が全ドメインで遮断されています。** PDFやページ本文を直接読めないため、
  「自社HPに決算公告PDFが実在することは確認できたが、本文の数値は取れない」という
  行が相当数あります。PDFを開ける環境なら回収できる見込みの行です。
- **WebSearch は1実行あたり200回**で、同時実行する波が分け合います。
- Google スプレッドシートへの直接書き込みはできないため、貼り付け用CSVでの納品です。

## 再開手順（コンテナが再起動した場合）

```sh
sh tokium/restore_scratchpad.sh          # /tmp を git の退避から復旧
python3 tokium/requeue_unverified.py 94  # 検索枠切れの行を次の波へ繰り越し
```
